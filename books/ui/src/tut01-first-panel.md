# A Panel Appears

By the end of this chapter a panel sits in the corner of a market-blue sky with a label in
it, you'll have moved it to every corner of the screen without recompiling once, and you'll
know the whole layout vocabulary the rest of the book builds on: nodes, anchors, pivots,
offsets, and size policies.

## Step 0 — create your project

From the repository root, the same move as every Fulcrum code-along — the workspace's
`games/*` glob picks the new crate up automatically:

```text
cargo new games/my-bazaar
```

Replace `games/my-bazaar/Cargo.toml`:

```toml
[package]
name = "my-bazaar"
version = "0.1.0"
edition = "2024"

[dependencies]
fulcrum = { workspace = true }
env_logger = { workspace = true }
# Manifest-only: lets #[derive(Component)] resolve the `bevy_ecs::` paths it generates.
bevy_ecs = { workspace = true }
```

And borrow the finished game's art — the street, the stall, a customer, and the skin
textures you'll use from chapter 4 (all generated by `tools/gen_bazaar_art.py`, no artist
harmed):

```text
mkdir -p games/my-bazaar/assets/ui
cp games/bazaar/assets/stall.png games/bazaar/assets/customer.png \
   games/bazaar/assets/ground.png games/my-bazaar/assets/
cp games/bazaar/assets/ui/*.png games/my-bazaar/assets/ui/
```

The layout files you will *not* copy. You'll type every one — they're the curriculum.

## Step 1 — a grid to draw on

UI lives in its own coordinate space: origin at the **top-left**, **+Y down**, measured in
**UI pixels** — virtual pixels that ignore the camera's position and zoom. How big that
space is depends on the camera's scaling mode, and the Bazaar pins it down hard.

`src/main.rs`, complete:

```rust,ignore
use fulcrum::prelude::*;

fn setup(mut ui: UiLoader, mut camera: ResMut<Camera2D>) {
    // A fixed 320x180 virtual grid: UI pixels are crisp integers on any window size.
    camera.scaling = ScalingMode::IntegerScale {
        width: 320.0,
        height: 180.0,
    };
    camera.center = vec2(160.0, 90.0);
    ui.load("ui/hud.ui.ron").expect("layout loads");
}

fn main() {
    env_logger::init();
    Fulcrum::with_config(FulcrumConfig {
        title: "my-bazaar".into(),
        window_size: (1280, 720),
        clear_color: Color::rgb(0.46, 0.65, 0.75),
        hot_reload: true,
        ..Default::default()
    })
    .insert_resource(AssetServer::new(concat!(env!("CARGO_MANIFEST_DIR"), "/assets")))
    .with_plugin(DefaultPlugins)
    .add_startup(setup)
    .run();
}
```

With `IntegerScale`, the UI space is *always* 320x180 — a 1280x720 window shows it at an
exact 4x, and resizing the window changes the scale factor, never your coordinates. Design
once, letterbox forever. It's the single most important decision for pixel-art UI, and it's
one line.

## Step 2 — the first layout file

Create `assets/ui/hud.ui.ron`:

```ron
Ui(root: Node(
    size: Fill,
    children: [
        Node(anchor: TopLeft, offset: (4, 4), size: Px((92, 24)),
            kind: Panel(color: (r: 0.13, g: 0.09, b: 0.07, a: 0.85)),
            children: [
                Node(id: "gold", offset: (7, 7), kind: Label(text: "Gold: 0", size: 8)),
            ],
        ),
    ],
))
```

```text
cargo run -p my-bazaar
```

A dark panel, top-left, saying `Gold: 0` in a chunky pixel font. Unpack what you typed:

> **Toolbox — `UiLoader`:** `ui.load("ui/hud.ui.ron")` parses the file and spawns one
> entity per `Node`, wired into a tree. That's the whole API — there are no builder calls,
> no widget constructors. It returns the root `Entity` (you'll want it in an exercise), and
> `ui.unload(root)` despawns the tree. The path is remembered on the root, which is what
> makes hot reload work in a moment.
>
> **Toolbox — `Node`:** every node answers four questions. *Where on my parent do I pin?*
> — `anchor`, one of nine points (`TopLeft` through `BottomRight`). *Which point of me sits
> on that pin?* — `pivot`, a fraction of my own size, `(0, 0)` top-left to `(1, 1)`
> bottom-right. *Nudge?* — `offset`, in UI pixels, +Y down. *How big am I?* — `size`:
> `Px((w, h))` exactly, `Fill` my parent, or `Fit` my content (the default). The root here
> `Fill`s the whole 320x180; the panel is pinned 4px in from the top-left corner.
>
> **Toolbox — the file format:** every field has a default, so you only write what you
> mean. `kind` is what the node *is*: `Panel` draws a colored rectangle, `Label` draws
> text, and a node with no `kind` is invisible pure layout. Colors are plain RGBA structs.
> The `id` string is the node's name for everything dynamic — chapter 2 lives on it.

The font is the engine's built-in Press Start 2P, and it's sharpest at multiples of 8 — on
a 320x180 grid, `size: 8` is body text and `16` is a headline. There is no font field to
get wrong; one game, one UI font (the recipes chapter shows how to swap it globally).

## Step 3 — prove it's data

Leave the game running. Open `assets/ui/hud.ui.ron` in your editor and, with both windows
visible:

1. Change `offset: (4, 4)` to `(40, 40)` and save. The panel moves — the file watcher
   despawned the tree and respawned it from disk, live. This is the styling workflow for
   the whole book: run the game, edit the file, look.
2. Change `anchor: TopLeft` to `Center`, save. The panel's *top-left corner* now sits at
   screen center — because the pivot is still `(0, 0)`. Set `pivot: (0.5, 0.5)` and save:
   now it's truly centered. Anchor picks the point on the parent; pivot picks the point on
   *you*. Every "why is it off by half a panel" bug in your future is one of these two.
3. Delete the `size: Px((92, 24))` line entirely, save. The panel shrinks to hug the label
   — that's `Fit`, the default, measuring its children. Put it back.

## Checkpoint

Your program should match `games/bazaar/examples/ui01_panel.rs` (which loads the same
layout as `assets/ui/ui01.ui.ron`):

```text
cargo run -p bazaar --example ui01_panel
```

New vocabulary:

| Term | What it is |
| --- | --- |
| node / tree | one entity from the layout file / all of them, parented |
| anchor | the point on the *parent* a node pins to |
| pivot | the point on *itself* it puts on the anchor |
| offset | pixel nudge after anchoring, +Y down |
| size policy | `Px` exact, `Fill` the parent, `Fit` the content |
| UI pixels | the virtual grid from the camera's scaling mode — here, 320x180 |
| `id` | a node's name for dynamic updates and clicks |

## Exercises

1. **The nine pins.** Without touching `offset`, place the panel flush in each corner and
   centered on each edge using only `anchor` + `pivot`. (Corner rule: the pivot that works
   is the anchor's own fraction — `BottomRight` wants `pivot: (1, 1)`.) Then add the 4px
   margin back with `offset` and notice which offsets need minus signs.
2. **A second label.** Add `Node(id: "day", ...)` under the gold label and give the panel
   `stack: Vertical(2)`. The two labels arrange themselves top-to-bottom with a 2px gap —
   that's a stack, chapter 2's main tool. What happened to the second label's `offset: (7, 7)`
   if you copied it verbatim? Fix it to `(7, 0)` and work out why the first one keeps both
   components.
3. **Two trees (harder).** `load` returns an `Entity`. Load the layout twice, keep both
   roots in a `Resource`, and unload one of them after five seconds (a frame system, a
   `Local<f32>` timer, `ui.unload(root)`). Two independent trees coexist happily — menus
   and HUDs usually ship as separate files. The reference chapter on layout files covers
   what `unload` tolerates.

The panel says `Gold: 0` and it will say `Gold: 0` forever — nothing is driving it. Next
chapter the market opens: customers arrive with somewhere better to be, and the HUD starts
telling the truth every frame.
